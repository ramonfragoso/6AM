# 6AM

A 3D game built with Next.js 15, React 19, React Three Fiber, WebGPU and Rapier physics. The scene holds a Corridor built from the Kit (modular Pieces exported from Blender), two Safe Rooms the Player Loops through (Passages through the doors, a Wrap that makes the door behind vanish), a first-person Player and a DebugPlayer that Flies through everything, plus lights, the physics world, Leva Tuning and the Debug toggle.

**Read `CONTEXT.md` before naming anything.** Use its terms in code, UI text and conversation, and avoid the words listed under _Avoid_.

## Commands

- `npm run dev`: dev server on http://localhost:3000
- `npm run check`: type check, ESLint and Prettier check. Run it before calling any work done.
- `npm run format`: ESLint autofix, then Prettier
- `npm run build`: production build

There is no test suite yet.

## Input

- `readGamepad()` (`input/gamepad.ts`) reads the first connected gamepad and returns a `GamepadState`: both sticks, both triggers and `pressed(button)`. With no gamepad it returns everything at rest, so callers never check for one.
- Buttons are named by position (`south`, `east`, `west`, `north`, bumpers, d-pad, `select`, `start`, stick presses), not by a brand's letters.
- Sticks are -1..1 with a deadzone, `x` positive to the right and `y` positive up (forward). Triggers are 0..1.
- It handles both the browser's `standard` mapping and unmapped pads (Linux reports triggers as axes).
- Gamepads are polled, not event driven: call `readGamepad()` inside `useFrame`, at `READ_INPUT_PRIORITY` (`world/physicsSettings.ts`, runs before `PHYSICS_STEP_PRIORITY`) when the result drives physics. Browsers only expose a gamepad after one of its buttons is pressed with the page open.
- Never branch on the device per action. Describe each control as an `InputAxis` (its keys plus a gamepad reader) and read it with `readAxis`, which merges both into one clamped -1..1 value. A feature's `use<Feature>Controls` hook owns its axes, as `player/usePlayerControls.ts` does.
- Camera following runs at the default priority 0, after the physics step, so it sees interpolated positions. Positive priorities take over rendering; avoid them.
- Presses (not held axes) are read by edge: `usePassageControls` (`passage/`) turns its `OPEN` axis (E, gamepad `south`) into `{ open }` true only on the frame it goes down. The DebugPlayer also uses E (Fly up), but only the viewed one reads input.

## Kit

- **Building with it:** a layout is a list of Placements (`kit/kitPieces.ts`). `KitInstances` draws every part of every Piece as one `InstancedMesh`, so a layout costs one draw call per part, whatever its size. It re-creates its meshes only when a Piece's count changes; moved Placements just rewrite the instance matrices. Re-creating meshes on every change is slow: three disposes the old render objects first, which drops their compiled shaders, so the new ones compile from scratch. `KitColliders` adds one box collider per solid Piece. New layouts are pure functions like `corridorLayout`.
- **Corridor Layouts** (`kit/corridorSpec.ts`): the House is fixed, `FIRST_CORRIDOR_LAYOUT` `6 | 4 F 6` before the Corner and `SECOND_CORRIDOR_LAYOUT` `6 | 4 | 6` after it: wall lengths (2, 4, 6 m), `|` a column pair, `F` a Door Frame. `kit/house.ts` holds the parsed tokens and `HOUSE_DOORS` (`houseDoors` in `corridorLayout.ts`). The doors are fixed (the start door at the start of the first Corridor, the Crucifix door at the end of the second) and are Safe Room doors, not Kit Pieces: `houseLayout` places no `door`, the Kit's `door` Piece is no longer in `KIT_PIECES` (Blender still exports it), the oak Floor starts exactly at the start door line and the Floor Tiles end exactly at the Crucifix door line, so neither shows inside a Safe Room. The Corner always follows the first Corridor. The Kit exports only the wall variants these layouts place (`WALL_PIECES` in `kit/kitPieces.ts`, `PLACED_WALL_VARIANTS` in `parts.py`); a layout that needs another one makes `wallPiece` throw, naming it. Left and right are as seen walking from the start door toward the Corner, which turns right (+Z).
- **Corner geometry** (`kit/corridorLayout.ts`, mirrored in `tools/kit/blender/granny_kit/pipeline/occlusion.py` for AO): the second Corridor starts on the Corner's turn-side column line (`COLUMN_INSET` inside the first Corridor's wall line), its walls are 1.05 m from its centerline, Narrow Columns sit on its joints, Floor Divisions cover ±0.2015 m around every column joint, and Floor Tiles fill the rest as a checkerboard, 4 tiles across (0.425 m) and whole rows of about 0.4 m between divisions (the row length adjusts by under 1 mm so rows end exactly at each division). Its roofs start 0.1455 m in, where `roof_corner` ends. Change constants in both files together.
- **Shadows:** Kit materials are double-sided, so `kitSurface` sets `shadowSide = BackSide` (only back faces go into shadow maps); without it every lit surface shadows itself in stripes. Kit meshes face outward, which this relies on. Transparent parts (Clear glass) cast no shadows, and neither do the Pieces in `SHADOWLESS_PIECES` (`kit/kitPieces.ts`): the Lantern, whose frame around its own Flame Light threw bar shapes across the walls.
- **Kit Surface** (`kit/kitSurface.ts`): every Kit material becomes a node material whose TSL multiplies the baked AO (red channel of the occlusion texture, second UV) into the color, so it also darkens point and area light, mixes in baked grime (green channel) and adds world-space brightness variation against texture repetition. Leva "Kit Surface" sets the strengths.
- **Exporting from Blender** (`/home/ramon/Downloads/house_interior.blend`, collection "Modular Kit"): the **Granny Kit** tab in the 3D viewport sidebar has an **Export Kit** button. It saves a temporary copy of the file, runs `tools/kit/blender/granny_kit/cli.py` in a background Blender, then `compress-model.mjs`, and writes `public/models/kit.glb`. Under `npm run dev` the game polls `/api/kit-version` and swaps in the new Kit without a page reload.
  - The add-on lives in this repo and is linked into `~/.config/blender/5.2/extensions/user_default/granny_kit`. Its preferences hold the game folder, Node.js, `ktx` (KTX-Software) and the bake device.
  - Each material is baked generically with Cycles from its own node tree into a repeating swatch (base color, ORM, normal), with its Mapping node moved into the UVs. Materials that cannot repeat (procedural, object or world coordinates, several mappings) are baked uniquely per Piece instead, and the panel lists them.
  - Each Piece gets AO and grime baked in context (surrounded by floor, roof, walls and drains as the Corridor places them) into its own texture on a generated second UV map. Walls are placed only as column variants (`__col_start`, `__col_end`, `__col_both`, as listed in `PLACED_WALL_VARIANTS`): the same geometry with AO baked against a column pair at that end, and `corridorLayout` picks the variant from the `|` marks. The plain walls are not exported; they stay in the bake for their geometry, UVs and as neighbors. A bake fits only one surrounding, so a Piece placed against different neighbors needs a variant per surrounding (`PLACEMENT_VARIANTS` in `parts.py`): the Corner's far column is `column_corner__far`, baked against the end wall and the second Corridor's wall, while `column_corner` is baked against the first Corridor's wall.
  - Blender's glTF exporter packs the AO image (red) together with a material's roughness/metallic image (green, blue) into one texture whenever the two are the same size, even though they use different UVs. The packed texture loses the grime (green) and ETC1S compression bleeds one channel into the other: the tiles' grout showed up in the AO at the atlas scale as a second, bigger grid. So `bake_piece` keeps a Piece's AO atlas apart from the sizes of its roughness/metallic textures (`roughness_texture_sizes`, `apart_from`: halved until it differs). Six Kit materials (chair, drain, the three picture frames, the square tabletop) were packed before this rule and get separate AO on the next Kit export.
  - Bakes are cached in `//assets/kit_gltf/cache` (by node tree, image and geometry) and KTX2 encodes in `node_modules/.cache/compress-model`, so a material swap re-bakes only that material. Tick **Rebake everything** to ignore the caches.
  - A material's **Texture size** (panel, or `granny_texture_size`) caps its textures. Large surfaces of Props (the small round table, the square table top, the chair) use 1024 px; everything small (books, bottles, candles, Lanterns, table parts, knobs, drains) uses 512 px.
  - A Piece's uniquely baked materials share one atlas with its own UV layout (`Unique` UV map, cached as `uvs.npz` next to the textures), sized from their Texture size: the largest chosen size × √(number of uniquely baked materials), rounded to the nearest power of two, so each gets about its chosen resolution (the round Table Set's candle, wick and two books share one 1024 px atlas). AO keeps its own atlas on the second UV.
  - Modifiers are applied at their **viewport** level, so Subdivision and Multires viewport levels decide the game's triangle count; render levels only affect Cycles. Props were lowered from 311k to about 69k triangles (square Table Set 40k, round Table Set 15.5k, Chair 8.7k, Lantern 4.8k each): bottles and candle holders at level 0 or 1, the candlestick holder's Multires at 1.
  - `compress-model.mjs` runs gltf-transform `join` after `dedup`: parts of one Piece that end up with the same material are merged into one mesh, so a Piece costs one draw call per material, not per Blender object. Anchor nodes get a glTF `extras` flag first, and `prune` runs with `keepExtras`, because empty leaf nodes are otherwise pruned.
  - Headless: `blender <file.blend> --background --factory-startup --python-exit-code 1 --python tools/kit/blender/granny_kit/cli.py -- '{"output": "<raw.glb>", "texture_dir": "<blend dir>/assets/kit_gltf", "cache_dir": "<blend dir>/assets/kit_gltf/cache"}'`, then `npm run kit:compress -- <raw.glb> public/models/kit.glb`.
- **Floor Tiles in the game** (`kit/kitSurface.ts`): materials whose name contains `__floor_tile_` sample their textures with a per-instance random offset and get a small per-tile brightness and roughness change (Leva Kit Surface `tileBrightness`, `tileRoughness`). The tilt and yaw jitter (±0.0175 rad, as in the Blender arrays) and the random 180° flip come from `corridorLayout`.
- **Game surface** (per material, in the Granny Kit panel): "Clear glass" exports a see-through material without textures: its Principled base color as the tint (a light gray when the shader is a node group), roughness 0.05 and an opacity of 0.15 + 0.6 × (1 − tint luminance), so dark glass hides more of what is behind it. The Lantern glass and the three bottle glasses use it. "Solid over darkness" exports the material opaque, multiplying its color by its opacity and by (1 − transmission). Use it for glass or translucent floors, since nothing is drawn behind them in the game. "Painting" skips baking: the material's image is exported on its own as `public/models/paintings/<image name>.ktx2` (UASTC, power-of-two size whose long side is the material's Texture size, 1024 by default), and the canvas gets a white placeholder the game replaces. Emission textures and strength export as they are.
- **Paintings** (`src/paintings`): Picture Frame Pieces `painting_frame_1` (brass), `_2` (wide) and `_3` (tall), both in the same wood (`Wood.002`, UV Per Meter 16.7). In Blender each is a frame object with the **Picture Frame** Geometry Nodes modifier: Width and Height are the visible painting size, the cross-section comes from the `frame_profile` curve, UVs follow each member in meters (UV Per Meter sets the grain size), so resizing never stretches the texture. The modifier's Painting Material is the canvas shown in Blender; every material with Game surface "Painting" (`painting_<image>`, with fake users) is exported. Paintings of one frame share its aspect: tall images were cropped at the bottom and wide ones at the right (`//assets/paintings`). `hangHousePaintings` puts the portrait on the Corner's end wall, the two wide paintings stacked on the first Corridor's first 6 m wall (left side) and Two Monks, Two Women Eating and Reading in a row, left to right as you face them, on its second 6 m wall (right side); the second Corridor has none. Leva Paintings › End Wall, › Left Wall and › Right Wall move each group (`along` the wall from its middle, center `height`, `size`, `depth` off the wall, and `gap` between frames for the groups) and rotate each painting (degrees: x leans, y turns, z tilts), in 0.001 steps. The frame, canvas and glass meshes stay alive while you tune; only their matrices change. All painting textures are preloaded, so swaps are instant: Leva Paintings `scaryPapa` (`papa_original` to `papa_scary`) and `scaryMonks` (`twomonks` to `saturndevouring`). The glass is the canvas geometry 2.5 mm in front, drawn black with additive blending, so it only adds light reflections (Leva `glassReflection`, `glassRoughness`); no transmission pass.
- **Props** (`src/props`): `square_table_set`, `round_table_set` and `chair` are one Piece each, so their Leva folders (Props › Square Table, › Round Table, › Chair: world `x`, `z`, `turn` in degrees, `size`) move and scale everything on a table together. Their origins sit on the floor under the table's center (the chair's under its middle), and AO is baked with only the floor around them, since they move. Each gets its own fixed `RigidBody` with a box collider, keyed by its Placement, so moving one rebuilds only its collider. The `lantern` Piece's origin is the column's origin (its `prefab_lantern` sits on `prefab_column`), so `lanternPlacements` reuses `firstCorridorColumns` (the column pair at every first-Corridor joint, including the Corner's `column`/`column_corner`) and adds Props › Lanterns `height`. The second Corridor has one Lantern, on its first column on the right wall (as seen walking toward the end door): `secondCorridorColumn` gives that `column_narrow` Placement, whose inner face matches the `column`'s to 3 mm, and `tiledLanternSpot` makes it the default of Leva Props › Tiled Lantern (world `x`, `z`, `turn`, `size`, and `height` on top of Props › Lanterns `height`). Its AO was baked against the first Corridor's column and walls.
- **Coat Rack** (`src/props/CoatRack.tsx`, `coatRack.ts`): its own Model, `public/models/coat_rack.glb`, exported like the Crucifix from the Blender collection "coat_rack" (a `prefab_coat_rack` empty on the floor under the pole parents the three Sketchfab hierarchies: rack, cloth, bowler hat). `useSurfacedModel` (`src/models`) clones the `kit_coat_rack` node and gives its materials `kitSurfaceMaterial`; Leva Props › Coat Rack sets world `x`, `z`, `turn` and `size` through the shared `useFurnitureControls`, and only the group's transform changes. Its fixed `RigidBody` holds one `CylinderCollider` on the pole (radius 0.31 m, height 2.608 m, scaled by `size`), keyed by its placement so only it rebuilds; the cloth and hat have none. Wood and cloth are 512 px, the hat is three plain colors with no textures, and AO is baked on one 1024 px atlas with no neighbors. Total about 10k triangles in five draw calls. Its default spot (x 8.5, z 14.4) is next to the end door, where the candle lights reach. Export as for the Crucifix, with `"collection": "coat_rack"`, texture_dir `<blend dir>/assets/coat_rack_gltf` and `npm run kit:compress -- <raw.glb> public/models/coat_rack.glb`.
- **Door Wall** (`src/doorWall`): the second Corridor's middle 4 m wall on the right, as seen walking toward the end door (`DOOR_WALL_INDEX`, `DOOR_WALL_SIDE`; it was on the left before) is a wall with a door that opens. `secondCorridorWall` gives that wall's Placement; `Corridor` drops it from the instanced layout with `withoutPlacement` (which throws if the layout no longer has it) but keeps it for the colliders, so the wall stays solid even with the door open. `DoorWall` draws three things:
  - `kit_wall_4m_door` from `public/models/wall_4m_door.glb`, at the old wall's Placement: a copy of the Kit's single-sided `wall_4m` mesh with a 1.658 × 2.968 m doorway cut through it (plaster UVs unchanged, no wainscot or top details).
  - The Kit's `door_frame` Piece minus its plaster door walls, turned 180° and 2 m along the wall (`doorFrameInWall`), as plain meshes. The Kit's `door` Piece is not used: its leaf is joined with its frame.
  - `kit_door_leaf` from the same file: the leaf, knob, knob plate and keyhole, with its origin on the hinge (`LEAF_HINGE`, the leaf's edge toward the start of the wall's run (the end door's side on the right wall, the Corner's side on the left), on its back face). Leva Door Wall `open` (degrees, 0 to 110) rotates it there, so it swings away from the corridor; only its matrix changes. `doorLeafMatrix` also takes negative angles: the leaf then turns around its front edge (`LEAF_THICKNESS` 0.2201 m in front of the hinge) and swings the other way, which the Safe Room doors use.
  - `DoorLight` (`doorLight.ts`), rendered by `DoorWallLight` in `Corridor` outside the models' Suspense so it exists from the first frame (see Lights under Performance): one shadowless spot light in front of the door, aimed at it, so the door can be lit without brightening the Tiled Lantern and the whole Corridor. Leva Door Wall › Light sets `intensity` (0 turns it off; it stays mounted, since adding or removing a light recompiles every shader), `color`, its position relative to the door (`out` into the corridor, `along` the wall, `height`), where it points (`aimHeight` on the door), the cone (`angle`, `penumbra`) and its falloff (`distance`, `decay`). Its helper shows with Debug on. It is a spot light, not a rect light: a `RectAreaLight` adds its two LTC lookup textures to every lit shader and would push the walls and Floor Tiles back over the WebGPU texture limit (see the shadow budget), while a spot light without shadows adds none.
  - In Blender (collection "corridor_wall_door"), `prefab_wall_4m_door` sits at the wall's origin and `prefab_door_leaf` on the hinge. The copies of the frame and the duplicate `.003` knob set only show the arrangement and are not exported.

- **Camera** (`src/camera`): `FieldOfView` sets the shared camera's `fov` from Leva Camera `fov` (30 to 150 degrees, default `DEFAULT_FOV` 80, also the initial camera in `World`) and calls `updateProjectionMatrix`. It serves the Player and the DebugPlayer, which both drive the same camera.
- **Player body** (`src/player/Player.tsx`): a capsule collider of fixed height (`PLAYER_HEIGHT`, 1.6 m) whose thickness is Leva Player `capsuleRadius` (0.1 to 0.6 m, default 0.3); the cylinder part shrinks as it grows, so the feet stay on the Floor. Changing it rebuilds only the Player's collider.
- **Underfloor** (`src/kit/Underfloor.tsx`): a black unlit 200 m plane just under the Floor (Leva Underfloor `depth`, 0.05 m below it, moved in place). Gaps between Pieces (drains, columns, the Door Wall) otherwise show the empty background, whose depth is the far plane, so the Fog paints it with full distance fog as light speckles. With the plane the ray ends right below the Floor and the gap gets the same Fog as the Floor around it. It adds no light and no shader variant.
- **Dust** (`src/dust`): one `Sprite` with `count = DUST_PARTICLES` (6000) and a `PointsNodeMaterial`, so every speck is an instanced camera-facing quad in one draw call (on a `THREE.Points` WebGPU draws 1 px points only). No buffers and no compute: each speck's spot comes from `hash(instanceIndex)`, wanders on slow sines and sinks with `fall`, and is wrapped with `mod` into a box `spread` wide and `height` tall that follows the camera on x and z (from the Floor up), fading near the box's edges so wrapped specks do not pop. `sizeNode` is in pixels: the speck's world `size` projected with the camera's focal length, clamped to `minPixels`..`maxPixels`; specks below `minPixels` lose alpha instead of shrinking, so far dust does not flicker. The round dot is drawn from the quad's UV (`softness`), so there is no texture. The material is unlit, additive and writes no depth, so it adds no light, shadow binding or shader variant elsewhere, and draw order against glass and Fires does not matter. Every Leva Dust value is a uniform set in place; `amount` hides specks by giving them zero size rather than changing the count, and `enabled` only toggles `visible`. Specks are lit by the scene's point and spot lights without being a lit material: every frame `readSceneLights` (`dustLights.ts`) copies up to `DUST_LIGHTS` (16) visible lights' world position, `distance`, color × intensity, `decay` and spot cone into fixed uniform arrays (empty slots get zero power), and the vertex shader adds up three's distance falloff and cone for each speck. So the dust flickers with the Flame Lights and follows their Leva values, at no recompile and no shadow binding, but walls do not block that light. Leva Dust `darkVisibility` is how visible dust is away from every light (0 shows it only near lights), `lightResponse` how much light brightens it, `lightLimit` caps it, and `lightTint` colors lit specks with their light. Since the dust writes no depth, the Fog fogs each speck by the depth of the surface behind it; if near dust gets washed out, draw it in its own pass after the Fog.
- **Post-processing** (`src/postprocessing`): `PostProcessing` is a `RenderPipeline` (`useRenderPipeline`, built by `createPostProcessing`) that renders the scene through `pass(scene, camera)`, so it takes over rendering at priority 1 (the one exception to the rule above). Camera matrices reach the effects as uniforms bound to the camera's own `matrixWorld`, `projectionMatrixInverse` and `position`, because the post-processing quad's camera is not the scene's. It starts on a black output (`LOADING_OUTPUT`; three's default is solid blue) until `showOutput` sets the real one. `createPostProcessing` returns a `dispose` that frees the scene pass's render target and the Fog's low-resolution and blur targets: `RenderPipeline.dispose()` only frees its own quad material, so without it every Fast Refresh of these files leaked about 40 MB at 1280×720 (hundreds at full screen and pixel ratio 2) until Chrome dropped the GPU device (`Instance dropped in popErrorScope`, then `createBuffer failed ... too large` for tiny buffers and a black canvas). Anything that owns render targets must dispose them the same way. A tab that lost its device stays broken until it is reloaded.
  - **Fog** (`volumetricFog.ts`, from three.js's `webgpu_postprocessing_fog` example): a ray march from the camera to the scene depth through a slab from the Floor up to `fogHeight`, with procedural cloud noise drifting in time, Beer-Lambert transmittance and a plain distance fog (`rangeFogNear`/`rangeFogFar`) on top. It renders at a fraction of the screen (`resolutionScale`, 0.4) into a one-channel target and is brought back to full size by depth-guided joint bilateral upsampling, a Gaussian blur or nothing (Leva Fog `denoiser`). The fog color is a flat Leva color: Flame Lights do not light it. Leva Fog: `enabled`, `fogColor`, `denoiser`, `resolutionScale`, `steps`, `density`, `cloudThreshold`, `cloudScale`, `maxRayDistance`, `heightFalloff`, `fogHeight`, `cloudSpeed`, `rangeFogNear`, `rangeFogFar`, `spatialSigma`, `depthSensitivity`, `blurRadius`. Everything but `enabled`, `denoiser` and `resolutionScale` is a uniform set in place; those three rebuild the pipeline's output node (a pipeline recompile, not a scene one). Disabled fog skips the march entirely.
  - **Lens** (`lens.ts`): a TSL remap of the screen UV, applied before the scene color, depth and fog are sampled. drei's `<Fisheye>` does not work with WebGPU (it needs `WebGLCubeRenderTarget` and a GLSL `ShaderMaterial`). Leva Lens `projection` picks Rectilinear (normal, the default), Equidistant, Stereographic, Equisolid, Orthographic (radial fisheyes) or Panini (vertical lines stay straight; `paniniDistance` appears only for it); `strength` blends from the normal lens to the projection and `zoom` crops toward the center (1 to 3). The camera's own picture is always rectilinear, so the Lens only redistributes the pixels it has: a fisheye gives the edges fewer pixels and the center more, so the center is enlarged and soft (about 1.6× at fov 80, 2.7× at fov 120 for Equidistant), and wide projections need a wide Camera `fov` to show anything. The extents are fitted on the CPU every frame (`matchLens`) so every output pixel has a source pixel and no corner goes black. Truly sharp fisheyes would need a cube-map render (several views) or a vertex-stage projection; neither is built.
- **Flames** (`src/props/flames.ts`, `Fires.tsx`, `FlameLights.tsx`): the only lights besides the ambient light. Every candle and Lantern wick has an `anchor_fire_*` empty in Blender (the flame base); the export turns `anchor_*` empties under a prefab into `kit_<piece>__anchor_*` nodes and `useKit` lists them as the Piece's `anchors`. Each fire anchor of each Placement gets:
  - a **Fire**: `FireMesh` from `@wolffo/three-fire/tsl/vanilla` (TSL ray-marched volume over a box, texture `public/textures/fire.png`), standing on the anchor. The library turns depth testing off, which would show fires through walls, so `Fires.tsx` turns it back on. Color, magnitude, lacunarity and gain are uniforms set in place; iterations and octaves are compiled into the shader, so changing them rebuilds that group's fire meshes. Fires scale with their Placement's `size`.
  - a **Flame Light**: a point light 40 % up the flame that casts shadows (512 px, near plane 2 cm so the candle and its holder shadow the table). Shadows are static: `shadow.autoUpdate` is off and every Leva change marks them for one re-render, so they cost nothing per frame. `flicker` only changes intensity in `useFrame`.
  - Leva Flames › Lanterns (first Corridor), › Tiled Lantern (the second Corridor's one Lantern, its own `tiledLantern` flame group passed to `flamesByGroup` by group rather than by Piece), › Candlestick (square Table Set), › Candle (round Table Set) each set the fire (`fireColor`, `magnitude`, `lacunarity`, `gain`, `iterations`, `octaves`, `width`, `height`) and its light (`light`, `lightColor`, `distance`, also the shadow range, `decay`, `flicker`).
- **Candle Sets** (`src/candles`): four Pieces, `candle_set_top_left`, `_top_right`, `_bottom_left` and `_bottom_right` (Blender collections of the same names inside "Modular Kit", each with a `prefab_candle_set_*` empty at (7, 0.75, 0): the start of a first-Corridor 2 m bay, on its centerline, where they were built). The top sets stand on the `wall_bottom_details` ledge, the bottom ones on the floor in front of it. Candles use one plain `candel` material (no textures, one draw call per set) with Subdivision at viewport level 1 (about 3.3k triangles each); AO is baked inside that 2 m bay with walls, columns and floor (`CANDLE_SET_PREFIX` in `occlusion.py`). Wicks have no geometry: each is an `anchor_fire_<set>_<nn>` empty (70 % up the old wick). In the game they stand in the tiled second Corridor, along the end of its last 6 m wall next to the end door, turned 90° so the Left sets are on the left walking in from the Corner, and moved 0.15 m toward their wall because that Corridor is narrower than the bay. Leva Candle Sets › Top Left, › Top Right, › Bottom Left, › Bottom Right set each set's world `x`, `z`, `turn`, `size`, and its one light (`lightHeight`, `light1X`, `light1Z`, in world meters; it does not follow the set). Only the bottom sets' lights cast shadows; the top sets' lights are shadowless (`SHADOWLESS_LIGHT_SETS` in `candleSets.ts`) to stay inside the shadow budget (see Performance). Candle Sets › Wax sets the wax `roughness` and `metalness` through the `candleWax` uniforms in `kitSurface.ts` (materials named `kit_candel__*`). Flames › Candle Sets sets the fire of all candles (starts cheap: 8 iterations, 2 octaves, small) and the light of all four Candle Set lights. `CandleSets` reuses `FireGroup` and `LitFlames`, so there is one Fire per wick but only one light per set. They have no collider.
- **Game surface "Glow"**: the material is exported as its own glTF material (name ending `__glow`) even when it shares a Piece's unique atlas, and `compress-model.mjs` marks such materials in `extras` so `dedup` and `join` keep them apart. The game gives it an emissive node (the Ceiling Lamp's disc).
- **Export pipeline notes:** material images missing on disk are left out with a warning, Ambient Occlusion shader nodes are baked as unoccluded (the Kit bakes its own AO), a Mapping node driven by a Value node still counts as a plain Mapping, a prefab without mesh parts is skipped with a warning, and textures whose pixels match within 1.5/255 (tinted copies of one material, like the door knob's three rusted irons) are exported once.
- **Memory:** an export needs about 4 GB on top of Blender. The button refuses to start when less is free; a long Blender session can grow past 10 GB, so save and restart Blender if it does.
- **Anchors:** to mark a spot inside a Piece for the game (where a fire burns, say), parent an empty named `anchor_<kind>_<name>` to its prefab. The game reads its position from `kit[piece].anchors`.
- **New Pieces:** in Blender, parent the parts to an empty named `prefab_<piece>` at the Piece's origin (on the 0.01 m grid), inside the "Modular Kit" collection, then add the name to `KIT_PIECES` (and to `SOLID_PIECES` if the Player should collide with it). Wall Pieces follow the left wall: they run along +X from their origin with the inner side facing −Y in Blender (+Z in the game). Duplicating a prefab's part with Shift+D keeps its parent, so the copy silently joins the Piece: clear the parent (Keep Transform) on copies used to dress the Blender scene. Every part of a Piece exports, wherever it stands.

- **Crucifix** (`src/crucifix`): its own Model, `public/models/crucifix.glb`, exported by the same pipeline from the Blender collection "crucifix" (a `prefab_crucifix` empty parents the brass `CROSS` and the downloaded Christ meshes `Object_2` to `Object_5`, which hang below `Sketchfab_model.002` and `gothic_crucifix`). It is not solid and has no fire.
  - The Christ's one material (`Krucyfiks`) has **Repack UV** ticked (`granny_pack_uv`, in the Granny Kit panel): the downloaded atlas keeps only 4 % of its area in use after the deleted parts, so it is baked uniquely into a new 1024 px atlas packed from the used UV islands only (4 px margin, about 2.5 times the original texel density), with AO on the same islands. The brass cross is a normal swatch (512 px, shared with the picture frame). The Christ has 59.6k triangles in four meshes that `join` merges into one draw call; the cross is a second one.
  - Export, headless (about 10 s on a copy holding only the crucifix; it loads the whole .blend, so check memory first as for the Kit): `blender house_interior.blend --background --factory-startup --python-exit-code 1 --python tools/kit/blender/granny_kit/cli.py -- '{"output": "<raw.glb>", "texture_dir": "<blend dir>/assets/crucifix_gltf", "cache_dir": "<blend dir>/assets/crucifix_gltf/cache", "device": "CUDA", "collection": "crucifix"}'`, then `npm run kit:compress -- <raw.glb> public/models/crucifix.glb`. The panel's Export Kit button only exports "Modular Kit".
- **Clock Table** (`src/clock`): the Model `public/models/clock.glb`, from the Blender collection "Clock alarm dekad". Six Pieces: `clock` (body, chrome, dial; `prefab_clock` at the center of its base), `clock_glass`, `clock_hand_hour`, `_minute`, `_second` and `round_table` (a linked copy `clock_round_table` of the Kit's `SmallTable`, so editing the table's mesh changes both). A `prefab_` empty nested inside another prefab is its own Piece (`descendants` in `parts.py` stops at it): each hand's prefab sits on its pivot under an `anchor_hand_<hand>` of the clock, and the glass is its own Piece. That keeps them out of the clock's AO bake (the hands rest at 12 and would leave their shadow on the dial; the glass, 3 mm in front of the dial, turned it black) and out of `join`, so the hands stay separate nodes. The clock's AO is baked standing on the table (`CLOCK` in `occlusion.py`); the glass and hands at tabletop height with no neighbours; the table like the other floor Props. Materials: `clock body` (black, 256 px, also on the hands, whose UVs all sit on one black texel of it), `clock dial` (512 px Swatch, diffuse only; its image node repeats, which looks the same since the mapped UVs stay inside 0..1, and keeps the dial out of a unique atlas), `clock chrome` (constants), `clock glass` (Clear glass). The table ships at 256 px and the game swaps in the Kit's `Small_table` textures (`kitTexturesOf`). About 5.5k triangles (table 2.6k) and 8 draw calls; 315 KB.
  - **Placement and the Wrap**: everything in a Safe Room must survive the Wrap, so the table stands in room space: Leva Clock › Table (`x`, `z` from the Start Room's center, +z toward its door; `turn`, `size` of table and clock together) and Clock › On Table (`x`, `z` on the tabletop, `turn`, `size` of the clock alone). `furnishedRoomMatrix` (`safeRoom/furnishedRoom.ts`) puts it in the room the Player is in or entering (`loopState.lampRoom`), turned half around while they are in the House; when a Passage into a room begins (door still shut) it moves there, and the Wrap carries it back to the same spot in the Start Room along with the Player, so it never visibly moves. `useFurnished` writes the group's matrix and its fixed `RigidBody` (one `CylinderCollider`, rebuilt only when `size` changes) at `FURNISH_PRIORITY`, after the Passage reads input and before the physics step. Default spot: the side of the Start Room away from the door's hinge (the leaf never sweeps it), in view at spawn, the clock facing the spawn point. All materials use `ROOM_SURFACE` (no world variation; Leva Safe Room `occlusion`, `grime`).
  - **Time and the Glitch** (`clockTime.ts`): the Clock can count only one minute. `clockTime.stuckAt` is the minute it is stuck in (seconds since midnight: `clockTime.hour`, the Night's Hour, plus Leva Clock › Time `minute`, :00), `clockTime.elapsed` runs at `clockTime.rate` (Leva `rate`; 1 is real time) through a 63 s cycle: 60 s counting (`second` starts at Leva `second`), then the minute Hand jumps one minute and both stop for `STALL_SECONDS` (1), then the Glitch for `GLITCH_SECONDS` (2): each Hand steps in three runs of alternating direction (second Hand 2 to 6 marks per run, starting clockwise; minute Hand 1 to 3, random start), spread evenly over the 2 s, random per cycle. Then both snap back to the stuck minute and zero seconds. `clockFace()` turns the time into a `ClockFace` (`hour` in seconds, `minute` and `second` in marks, `phase`), so a jump in time or a slow frame always lands on the right face. The hour Hand belongs to the Night: `showHour(hour)` sets `clockTime.hour`, restarts the minute (Leva `minute` and `second`, cycle 0) and emits `ring`; `setClockHour` does the same silently (a new Night) and `ringClock` only rings (Dawn). A restart bumps `clockTime.restarts`, and `useClockHands` emits no face events across one, so a restart never clunks or ticks. `useClockHands` redraws the Hands only when the face changes, and turns face changes into `clockEvents` (`tick`, `stall`, `glitchStart`, `glitchStep` per Hand, `reset`, `ring`). Anything that reacts to the Clock (its Sounds now, later anything else) listens to `clockEvents.listen` and never polls the time.
  - **Sounds** (`useClockSounds`): one Sound Emitter on the Clock (the on-table group), whose presence is `loopState.lampLevel`, so it is heard only in the Safe Room and fades out with the Passage. `tick` alternates `clockTick`/`clockTock`, `stall` and `reset` play `clockClunk`, `glitchStart` plays `clockGlitch` and every `glitchStep` a tick pitched up (second Hand) or a tock pitched down (minute Hand), with jitter; `ring` plays `clockRing`. Leva Clock › Sound: `volume`, `tick`, `glitch`, `ring`, and the emitter's `distance`, `rolloff`, `maxDistance`. The files are placeholders synthesized by `python3 tools/sounds/clock_sounds.py` (numpy, ffmpeg with libopus); replace them with recordings of the same names.
  - **Export** (about 30 s): save a copy of the open file (in Blender, `bpy.ops.wm.save_as_mainfile(filepath=<copy>, copy=True)`), make a lean copy with `tools/kit/blender/lean_copy.py`, which keeps only the named collections plus a context collection, clears fake users and sets export-only texture sizes: `blender <copy> --background --factory-startup --python-exit-code 1 --python tools/kit/blender/lean_copy.py -- '{"output": "<lean.blend>", "collections": ["Clock alarm dekad"], "context": {"name": "clock_context", "prefabs": ["prefab_floor"]}, "texture_sizes": {"Small_table": 256}}'`, then `blender <lean.blend> --background --factory-startup --python-exit-code 1 --python tools/kit/blender/granny_kit/cli.py -- '{"output": "<raw.glb>", "texture_dir": "<blend dir>/assets/clock_gltf", "cache_dir": "<blend dir>/assets/clock_gltf/cache", "device": "CUDA", "collection": "Clock alarm dekad", "context_collection": "clock_context"}'` and `npm run kit:compress -- <raw.glb> public/models/clock.glb`. Add `"force": true` after moving a hand or anchor.
- **Sound** (`src/sound`): one `AudioContext` (Web Audio, no library), created on the first key, click or touch (`useAudioUnlock`; browsers keep audio locked until then). `SoundSystem` in `World` holds the unlock, the listener (`useSoundListener` copies the camera into `context.listener` when it moves) and Leva Sound (`master` and one volume per Bus).
  - **Adding a Sound**: put the file in `public/sounds/<feature>/`, add it to `SOUNDS` (`sounds.ts`) with its Bus and base `volume`, call `preloadSounds([...])` from the feature, and `playSound(name, { from, volume, rate })`. Files are fetched at preload and decoded once the context exists; `playSound` does nothing until the buffer is decoded, so it never stalls. Each play costs one `AudioBufferSourceNode` and one gain, freed when it ends, so overlapping plays are fine.
  - **Positional Sounds**: `useSoundEmitter(objectRef, { bus, shape, presence })` makes one `PannerNode` (HRTF, inverse distance) that follows the object's world position (written only when it moves) and a presence gain read every frame (set only when it changes, smoothed), which is how a Sound is limited to a place: the Clock passes the Safe Room's light level. Pass the emitter as `from`. Walls do not block sound; use presence for that.
  - **Buses**: `effects`, `ambience`, `music`, each a gain into the master. Background loops and music go on `ambience` and `music` (add a looping play when they arrive).
  - **Formats**: Ogg Opus (`.ogg`, 48 kHz, mono for positional Sounds, about 64 kbps). Opus decodes to the same buffers as WAV, is the smallest at that quality, and its Ogg packing loops without the gap MP3's padding adds. Chrome, Firefox and Safari 18.4+ decode it; add an MP3 next to it only if older Safari matters.
- **Hidden faces**: the unwrap reveals faces hidden in Edit Mode on the export copies before selecting (`edit_uv_layer`); before, a hidden face kept zero AO UVs and baked black (the clock glass was hidden).

## Safe Rooms and the Loop

Decision record: `docs/adr/0001-loop-by-wrap-between-two-safe-rooms.md`.

- **Rooms** (`safeRoom/safeRooms.ts`): two fixed Safe Rooms built from one Model. The Start Room sits behind the start door, the End Room behind the Crucifix door (`SAFE_ROOMS`, from `HOUSE_DOORS` via `roomBehind`). Room-local space has its origin on the Floor at the room's center, +Z toward its House door: the door line is at z = `DOOR_LINE` (2.05 m), the interior faces at ±1.95 m and ±2 m, the ceiling at `ROOM_HEIGHT`.
- **Paired parts**: every part appears twice, turned half around the center (`ROOM_PARTS`): `safe_room_half` (one side wall, half the Floor, half the ceiling) and `safe_room_doorway_wall` at identity and at a half turn, plus the `ceiling_lamp`. So a room looks the same turned 180°, which the half-turn Wrap needs. The Start Room's far doorway wall (with its door) and `safe_room_full_wall` are shown in turn from `loopState.startRoomFarDoor`: the far door while the Player is out in the Corridors, the full wall once they are inside. It only switches out of sight. The halves are baked without the doors as neighbours (`DOORLESS_SAFE_ROOM_PIECES` in `occlusion.py`): each half reaches both doorways, so the jambs' contact shadows showed as dark marks on the Floor in front of the full wall; at a real door they sit under the jamb anyway. Hidden parts get a zero-scale instance matrix, never `visible = false`, so their pipelines compile at load.
- **Doors** (`useSafeRoomDoors`): each of the four doorways (`DOORWAYS`: `startNear`, `startFar`, `endNear`, `endFar`) gets the Kit's `door_frame` minus its plaster (`framePartsOf`) and the Door Wall Model's `kit_door_leaf`, both instanced, at `doorFrameMatrix`. The leaves swing with `loopState.leafAngles`: positive into the room, negative toward the Corridor (around the leaf's front edge). The far doors never open. The exteriors (`safe_room_exterior` at the start door, `safe_room_exterior__end` at the Crucifix door) close the Corridor ends and use the Kit's plaster textures through `kitTexturesOf`.
- **No world-position variation** in a room: room parts, their doors and the Ceiling Lamp use `kitSurfaceMaterial(..., ROOM_SURFACE)` (`worldVariation: false`), so the two rooms and both halves of a room look identical. The exteriors keep world variation (they face the Corridors). `ROOM_SURFACE` also takes the AO and grime strengths from `safeRoomSurface` (Leva Safe Room `occlusion`, `grime`) instead of Kit Surface's, so the rooms are tuned on their own.
- **Instancing drops tangents** (`partInstances.ts`): three r186's instancing transforms positions and normals but not tangents, so a normal-mapped `InstancedMesh` whose instances are turned (the Start Room is turned 90°) gets a degenerate tangent frame: at view angles just off an axis the walls went black. Safe Room instances use a copy of the geometry without the `tangent` attribute (three then derives the frame from screen-space derivatives) and flip `normalScale.y`, as `GLTFLoader` does for derivative tangents. The Kit's own instanced Pieces still use vertex tangents and can show the same artefact on turned Pieces (the second Corridor); apply the same treatment there if it shows.
- **Fog and Dust stop at the room walls** (`safeRoomVolumes.ts`): the Fog computes each room's enter and leave distance along the view ray once (`safeRoomSpans`), skips its march samples inside them and subtracts them from the distance fog; each Dust speck tests the two room boxes (`outsideSafeRooms`). Written as `Fn`s with `.toVar()` intermediates: as plain nested TSL the ray-box test was inlined at every use and the Fog shader took 20 s to compile.
- **Lamp Shadows**: the Lamp Light is shadowed without a shadow map. `LampLight` sets `castShadow` with `shadow.shadowNode = lampShadowNode` (`lampShadow.ts`), three's hook for a custom shadow term, so three renders no shadow map and binds no cube texture. `lampShadowNode` returns each material's own visibility (`shadeFromLamp` registers it, and appends the kind to the material's program cache key): Safe Room parts multiply the blue channel of their occlusion texture (baked in Blender, see below) with the Furniture Shadow; the Clock Table's materials get only the Furniture Shadow; every other material gets 1. It multiplies only the Lamp Light (diffuse and specular), not the ambient or Flame Lights, so Leva Ceiling Lamp `color`, `light` and `flicker` still drive it.
  - **Baked** (`occlusion.py`, `lamp_visibility`): for the four room parts, after the AO bake, the export puts a point light (radius `LAMP_RADIUS` 1.8 cm, just under the paper disc) at the lamp's `anchor_light_ceiling_lamp`, bakes Cycles' direct diffuse light twice (shadows on, then every object's `visible_shadow` off) and stores the ratio, so only the geometry's shadowing is baked, not the light's falloff or color. Cycles' SHADOW bake gave values above 1 and 1 where no light reaches, so it is not used. Each part is baked in the same symmetric room as its AO: the lamp at the center, both doorway walls with their doors, the halves without doors (`DOORLESS_SAFE_ROOM_PIECES`), the full wall without the far door. So the shared, half-turned textures stay correct in both rooms, after the Wrap and with the far wall either way. The disc sits 2 cm above the light, so the ceiling and the very top of the walls get none of it. The Clock Table is not in this bake: it moves, and the halves share one texture, so its shadow would show twice.
  - **Furniture Shadow** (`furnitureShadow.ts`, `useFurnitureShadow`): a 512 px half-float texture holding 1 / distance from the lamp of the Clock Table's surfaces (table and clock, not glass or Hands), drawn from a camera at the Lamp Light aimed to fit the table. It is drawn again only when the table's world matrices or the lamp's position change (tuning, or the table following the Player between rooms), never per frame. Room and table materials compare their own distance against it with a 3×3 filter. Only those materials sample it, so other shaders gain no binding.
  - Leva Safe Room › Lamp Shadows: `baked` and `furniture` (0 to 1 each; 0 lights everything), the Furniture Shadow's `softness` (texels) and `bias` (meters).
  - **Compression**: `compress-model.mjs` encodes an occlusion-only texture whose blue channel is in use as UASTC, not ETC1S: ETC1S bleeds three uncorrelated channels into each other. The four room parts' occlusion textures are about 1.2 MB together.
- **Lamp Light** (`LampLight`, `useLampLight`): one point light at the Ceiling Lamp's `anchor_light_ceiling_lamp`, in the room named by `loopState.lampRoom`, at `light` times `loopState.lampLevel`. It is mounted in `Corridor` outside the models' Suspense (with the Door Wall light), stays at 0 until `safe_room.glb` has loaded, and fades to 0 while the Player is in the Corridors because a shadowless light shines through walls. The round `paper` disc (material `kit_paper__ceiling_lamp__unique__glow`) gets `emissiveNode = ceilingLampGlow`, the same color times `glow` and the same level and flicker. Leva Safe Room › Ceiling Lamp: `color`, `glow`, `light`, `distance`, `decay`, `flicker`.
- **House lights** follow `loopState.houseLevel`: Flame Lights and Candle Set Lights (`waver` in `FlameLights.tsx`) and the Door Wall light (`useHouseLightLevel`). Only intensity changes, so nothing recompiles.
- **Colliders** (`SafeRoomColliders`, in `Corridor` outside the Suspense so the spawning Player never falls through): per room a Floor box and four wall boxes; the doorway walls are solid because doors are always shut when the Player has control.
- **Passage** (`passage/passage.ts`, `usePassage.ts`): when the Player is within Leva Prompt `reach` of a door's middle, on the side it opens from (`DOOR_CHOICES` by `loopState.whereabouts`: from inside the Start Room its door; from the Corridors the start door and the Crucifix door) and looking within `facing` degrees of it, the Prompt fades in; E or `south` starts a Passage. The body is disabled and the camera follows `passageMoment` over Leva Passage `duration`: line up (face the door, level the pitch), open, through (a bow away from the hinge of up to `curve` meters, different each time by `curveVariation`), close, each eased in and out at the shares in Passage › Timing. During it the lamp and House levels cross-fade. At the end the leaf is shut and, when entering a room, the Wrap moves the Player into the Start Room (`wrapIntoStartRoom`: the room entered, turned half around, mapped onto the Start Room), the far wall turns full and the Player regains control. The camera stays on the held pose until the next physics step (`useAfterPhysicsStep`), so Rapier's interpolation never shows the teleport.
- **Spawn** (`passage/spawn.ts`): where a Passage into the Start Room ends, facing its door.
- **Prompt** (`passage/Prompt.tsx`): the "Press E" `<p>` rendered by `World` outside the canvas; `usePassage` sets its opacity (Leva Prompt `fade`). The page font is Cinzel Decorative (`next/font/google` in `app/layout.tsx`); Leva and the DebugPlayer readout keep theirs.
- **Disposal**: Safe Room meshes and materials are freed with `useDisposeWhenDropped`, which waits a tick and cancels if the same value mounts again. React Strict Mode runs every effect cleanup once in development; disposing GPU buffers there flooded Chrome with "used in submit while destroyed".
- **Export** (Blender collection "safe"): prefabs `prefab_safe_room_half`, `_doorway_wall`, `_full_wall`, `_exterior` (all at the room's symmetry center, x 17.55687, y 8.97872 in Blender) and `prefab_ceiling_lamp` (with the light Anchor); `prefab_safe_room_door` (the door copies) has the custom property `granny_context_only` (baked as a neighbour, never exported). `granny_occlusion_size` on a prefab overrides its AO atlas size (2048 asked for the room parts, which the 2048 px tile swatch halves to 1024 so Blender does not pack them; 1024 for the exterior, 256 for the lamp). `PLACEMENT_VARIANTS` adds `safe_room_exterior__end`. `preview_safe_room_half` is a linked copy only for the Blender view. Tiles are 2048 px, the lamp 256 px; the exterior's plaster is set to 256 px only for this export because the game swaps in the Kit's. Headless, on the saved file (Cycles syncs the whole scene for every swatch bake, so cap memory at about 10 GB, not 6):

  Make a lean copy first (about 1 min in all, 10 GB memory cap): save a copy of the open file, then `blender <copy> --background --factory-startup --python-exit-code 1 --python tools/kit/blender/lean_copy.py -- '{"output": "<lean.blend>", "collections": ["safe"], "context": {"name": "safe_context", "prefabs": ["prefab_wall_2m", "prefab_roof", "prefab_drain", "prefab_floor", "prefab_floor_tile_1", "prefab_floor_tile_2"]}, "texture_sizes": {"Painted Plaster Wall.001": 256}}'`, then `systemd-run --user --scope -p MemoryMax=10G -p MemorySwapMax=0 blender <lean.blend> --background --factory-startup --python-exit-code 1 --python tools/kit/blender/granny_kit/cli.py -- '{"output": "<raw.glb>", "texture_dir": "<blend dir>/assets/safe_room_gltf", "cache_dir": "<blend dir>/assets/safe_room_gltf/cache", "device": "CUDA", "collection": "safe", "context_collection": "safe_context"}'` and `npm run kit:compress -- <raw.glb> public/models/safe_room.glb`. The lean copy drops the paintings' fake users, so the summary lists none and the compressor re-encodes none. (Before the lean copy, the 256 px plaster override was not applied and the file shipped 2048 px plaster the game never used: 4.0 MB, now 1.9 MB.)

  `context_collection` builds only `CONTEXT_PIECES` (2 m wall, roof, drain, floor, Floor Tiles) of that collection as bake neighbours. The occlusion cache key covers the neighbours and their matrices but not the baked Piece's own placement: after changing only a target matrix in `recipe`, export with `"force": true`.

## Nights, Hours and Haunts

The Exit 8 rules on top of the Loop. Terms (Night, Hour, Loop, Haunt, Loud, Subtle, Clean Loop, Armed, Trigger, Manifest, Haunt State, Caught, Missed, Haunt Rule, Dawn) are in `CONTEXT.md`.

- **Night** (`night/night.ts`): `nightState` is a module-level store, read every frame and never through React state: `night`, `hour` (0 to `FINAL_HOUR` 6), `phase` (`playing`, `dawn`), `loop` (the current Loop: outcome, Haunt, `stage` `armed`/`manifested`, odds, the rules that fired, `forced`), `loops` (one `LoopRecord` per finished Loop), `standings` and `refills` (the pool). Importing it starts Night 1 with its first Loop chosen, so a page load is a new Night. `startNight` (Play again, Haunts › Testing › New Night) starts the next one and emits `newNight`; `usePassage` respawns the Player at `startRoomSpawn` on it.
- **Verdict** (`endLoop(way)`): `usePassage.finish` calls it after the Wrap of every Passage into a room, with `back` for the start door and `ahead` for the Crucifix door (`WAY_THROUGH`). `passes` (`night/loops.ts`): a Loop holding a Haunt, Manifested or not, passes by going back, a Clean Loop by going ahead. A Manifested Haunt is Caught when the Loop passed (out of the pool) and Missed when it failed (stays in). Then: passed at Hour 6 → Dawn (`ringClock`, `dawn` event); otherwise the Hour goes up one or back to 0, `showHour` moves the hour Hand and rings, and the next Loop is chosen. `nightEvents`: `verdict`, `dawn`, `newNight`.
- **Choosing a Loop** (`haunts/drawLoop.ts`, pure): at the Wrap (and when a Night starts) the base weights for Loud, Subtle and Clean are blended by Hour between Leva Haunts › Odds at 12:00 and › Odds at 6:00, every `HAUNT_RULES` entry (`haunts/hauntRules.ts`) that is locked or switched on in Haunts › Rules multiplies them (×0 forbids), a kind without registered Haunts gets 0, and all zero means Clean. Then a Haunt of that kind is picked evenly from its unCaught Haunts, never the previous Loop's Haunt when another is left. **A new rule** is one entry in `HAUNT_RULES`: a `name`, a `hint` (its Leva checkbox hint), `locked` (always on, no checkbox) and `weigh(night)`, which sees the Hour and every past `LoopRecord` and returns factors per outcome or `null` (did not fire). `firstLoopClean` is locked; `noThirdCleanInARow` and `fewerLoudInARow` start off.
- **Pool** (`haunts/pool.ts`): each Haunt has `inPool`, `caught` and `missed`. When every Haunt of a kind is Caught, `refillEmptyKinds` puts them all back and counts the refill, so the odds never change because a kind ran out.
- **A Haunt** (`haunts/haunts.ts`) is an `id`, a `name`, a `kind` (`loud`, `subtle`), an optional `trigger(moment)` and an optional `haunt(state, moment)`. Register it in `HAUNTS` (`haunts/allHaunts.ts`), which now holds the 20 mocks of `mockHaunts.ts` (Haunt 1 to 10 Loud, 11 to 20 Subtle; odd ones have no Trigger, even ones `reachedCorner`; they change nothing). Without a Trigger a Haunt Manifests as soon as it is chosen; with one, `useHauntLife` (at `HAUNT_PRIORITY`, before the physics step) tests it every frame while the Player is in the House and calls `manifestHaunt`, which emits `hauntEvents` `manifest` (for a Sting later). From then on `haunt(state, moment)` runs every frame with `moment.eye`, `yaw` (`player/playerPose.ts`, the Player's eye even while the DebugPlayer is viewed), `sinceChosen` and `sinceManifest`. Trigger helpers live in `haunts/triggers.ts` (`pastX`, `within`, `reachedCorner`). Give every Trigger a spot on the way to the Crucifix door.
- **Haunt State** (`haunts/hauntState.ts`): the values Haunts change, each with its Clean value in `CLEAN_HAUNT_STATE`; `resetHauntState` restores them whenever a Loop is chosen (the doors are shut then). Features read it every frame and never know which Haunt runs: `houseLight` multiplies the Flame Lights, Candle Set Lights and the Door Wall light. Add a value there, read it where it applies, and keep to the Performance rules: a Haunt dims, moves or swings what exists (light intensity, matrices, uniforms); it never adds or removes lights, meshes or materials.
- **Debug overlay** (`haunts/HauntOverlay.tsx`, outside the canvas): Leva Debug › `haunts` (separate from `enabled`) shows the Night, Hour, whereabouts, this Loop with its stage and passing direction, the last Loop, the odds, the rules that fired and every Haunt's standing (unseen, Caught, Missed, refilled; the current one outlined) with refill counts. It polls `nightState` four times a second.
- **Haunts › Testing** (`night/useNightTesting.ts`): `nextLoop` (Draw, Clean or a Haunt) forces every Wrap's choice, skipping the rules, and re-chooses the current Loop at once while the Player stands in the Start Room; Hour +1 / Hour −1 move the Hour (and the Clock); New Night. Leva folders named `Testing` are never written to `tuning.json` (`UNSAVED_FOLDER` in `useTuningPersistence`).
- **Dawn** (`src/dawn`): on `dawn` the Player keeps no control (`usePassage` holds them), `DawnScreen` (outside the canvas) releases the pointer lock and fades to black while `fadeAllSound` (a gain after the master) fades every Sound, then shows Play again (click, E, Enter or gamepad `south`). Play again locks the pointer again and calls `startNight`; the screen and the Sound fade back in. Leva Dawn: `fadeOut`, `buttonDelay`, `fadeIn`. A real ending scene replaces `DawnScreen`; the Night logic does not change.

## Performance

The game must stay fast on the owner's machine (RTX 2060, Linux). Follow these rules for every new Piece or feature:

- **Draw calls:** each Piece costs one draw call per material for all its Placements (`KitInstances` instancing plus the `join` in `compress-model.mjs`). Keep the number of distinct materials in a Piece low, and prefer adding Placements over new Pieces.
- **Triangles:** check a new Piece's triangle count before exporting (viewport modifier levels apply). Small props should stay in the low thousands; lower Subdivision and Multires viewport levels rather than decimating by hand.
- **Textures:** everything ships as KTX2 (ETC1S for color and ORM, UASTC for normal maps and paintings). Set each material's Texture size: 1024 px for large surfaces, 512 px for small props, 256 px for tiny ones. Never ship 2048 px for a prop.
- **Never re-create meshes or materials on a tuning change.** Keep object counts stable and update matrices, uniforms and material properties in place. Re-creation disposes the old render objects first, so three recompiles their shaders and the game stalls.
- **Lights:** every light is compiled into every lit shader, so changing how many lights exist recompiles the whole scene (seconds). Keep the light count fixed and animate intensity or color instead, and mount every light with the Kit, never behind a Suspense that resolves later (the Door Wall light and the Lamp Light are rendered in `Corridor` outside the models' Suspense for this reason; behind it they rebuilt every material a second time at startup). The scene has an ambient light (Dust is unlit and adds none), one Flame Light per fire (the top Candle Sets' are shadowless), the Door Wall's spot light and the Lamp Light, nothing else. The Lamp Light has `castShadow` on, but with a custom `shadowNode` (Lamp Shadows), so it has no shadow map and uses none of the shadow budget. A point light's shadow renders the scene six times, so shadow maps are static (`shadow.autoUpdate = false`, `needsUpdate` after a change); never let a point light re-render its shadow every frame.
- **Shadow budget:** every shadow-casting point light adds its cube shadow map (a texture and a sampler) to every lit shader, and WebGPU allows 16 of each per shader. Kit walls already use 4 (color, ORM, normal, AO), so more than about 11 shadowed point lights in the scene breaks their pipelines (`Invalid BindGroupLayout`, walls vanish while low-texture meshes still draw). There are 9 now: 5 Lanterns, the candlestick, the candle and the lights of the two bottom Candle Sets (the top sets' lights are shadowless and cost no binding). With 11 (when the top Candle Sets still had lights) the Floor Tiles lost their textures on WebGPU, so treat 9 or 10 as the ceiling. Every lit pixel also pays for each one (5 cube taps), so add point lights without shadows (`castShadow: false` on a `LitFlame`) once the budget is used.
- **No transmission:** a material with transmission makes three render the scene a second time. Glass uses Clear glass (alpha blended) or Solid over darkness, and the painting glass is additive.
- **Emissive is not a light:** an emissive material (or a Fire) only brightens itself. Light that should reach other surfaces needs a point light.
- **TSL:** a node used in several places is inlined at every use, so nested helpers can grow a shader combinatorially. Put reused intermediates in `.toVar()` and repeated logic in `Fn`, and compute per-pixel values once outside loops (see the Safe Room Fog cut-off). Measure startup with long-animation-frame entries after a warm reload, with Chrome restarted between runs.
- **Physics:** never remount the Corridor's `RigidBody` at runtime (it froze the game and could trap the Player inside a new collider). Movable things get their own small fixed `RigidBody`, keyed by their Placement.

## Conventions

- **Zero comments.** Express intent through names, extracted functions and named constants. Explanations of tuning values go in Leva hints (the last argument of `slider`). The lint rule only allows `eslint-disable` directives.
- **Hooks hold the logic**; components stay mostly markup.
- **"Tuning" means Leva sliders.** Each feature owns one `use<Feature>Tuning` hook, built with `useTuningControls` (never `useControls` directly) so saved values from `public/tuning.json` become the defaults. Save in the Leva "Tuning" folder writes that file through `PUT /api/tuning`, which only works under `npm run dev`.
- **Debug visuals** (collider wireframes, light helpers) are gated by `useDebugMode()`, which is off by default.
- Named exports everywhere, except the default exports Next.js requires in `src/app`.
- `"use client"` only at the client boundary, `world/World.tsx`.
- `@/` imports across folders, relative imports within a folder.
- Magic numbers become named constants.

## Formatting

Prettier (no semicolons, 100 columns) plus ESLint. The Claude Code hook `.claude/hooks/format-edited-file.sh` runs ESLint autofix and Prettier on every file Claude edits, and reports remaining lint errors back.

- Objects and type literals with 4 or more properties go one per line; up to 3 stay inline. ESLint enforces this.
- Prettier always collapses imports, destructuring and JSX props when they fit, so those are not enforced.
- If `object-curly-newline` keeps failing on an inline type annotation, extract a named type.
- ESLint deliberately allows `any` and unused variables. Do not turn those rules back on.

## Constraints

- The dev server uses webpack, not Turbopack, because Turbopack runs worse on the owner's machine. Do not add `--turbopack`.
- Next.js stays on 15.3 until an upgrade is done as its own task.
- Leva must stay at 0.10.1 or later: in 0.10.0, slider hints crash the panel with "`Tooltip` must be used within `TooltipProvider`".
- The renderer is `three/webgpu` with a WebGL fallback. Use node materials and TSL, not `ShaderMaterial`, GLSL or WebGL-only postprocessing.
- The browser for WebGPU is the system Chrome 155 (`/opt/google/chrome/chrome --enable-unsafe-webgpu --enable-features=Vulkan,VulkanFromANGLE,DefaultANGLEVulkan`). The Chrome DevTools MCP browser has no GPU: the page cannot create a renderer there, so drive Chrome 155 yourself (a separate `--user-data-dir`, `--remote-debugging-port`) to check anything visual.
- `world/identitySwizzle.ts` drops the `swizzle: "rgba"` that three r186 puts on every WebGPU texture view. Chrome 151+ (so 155) accepts the string; older builds such as Chromium 141 type `swizzle` as an object, the spec's older draft, and throw on it (`Failed to execute 'createView' on 'GPUTexture'`). `rgba` is the default anyway. Remove the shim once a three release stops sending the string or nobody runs pre-151 browsers.
- No 3D textures (`Data3DTexture`, `texture3D`): three always gives them `RENDER_ATTACHMENT` usage, and the upload fails validation on older Dawn (Chromium 141), leaving them empty; `generateMipmaps` is also on by default and breaks them. The Fog's noise is procedural TSL (`mx_fractal_noise_float`) for this reason.
